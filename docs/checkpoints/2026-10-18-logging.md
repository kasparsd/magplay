# Structured logging local evidence — 2026-10-18

Local evidence for the [logging architecture](../logging.md) and [implementation plan](../plans/structured-logging.md). This is not a real-server or device measurement.

## Generated-media comparison

`docs/checkpoints/2026-10-18-logging/benchmark.mjs` compared synthetic local-file preparation with telemetry disabled and enabled, in separate processes. It did not exercise HTTP, Docker, a browser, or a public swarm. Raw samples are in [benchmark.json](2026-10-18-logging/benchmark.json).

Six passes of direct, remux, and a 30-second seek showed no material overhead. Cold direct preparation was 37.8 ms disabled and 43.1 ms enabled. Cold remux was 159.8 ms and 158.5 ms. Cold seek-to-playable-output was 124.7 ms and 127.3 ms. Warm direct stayed under 0.2 ms either way; warm remux and seek stayed in the same 117–128 ms band. Node CPU for the run rose from 69.8 ms to 76.7 ms, and resident memory from 82.5 MiB to 83.3 MiB. Event-loop p99 was 11.4 ms in both processes.

With telemetry enabled the run emitted 131 records (53,486 bytes) and 59 metric series, all retained in the Debug tail. The disabled run emitted none. That volume is the fixture's own lifecycle, not a capacity claim.

## What this does not establish

Server startup, seek latency, ffmpeg CPU, long-session cache growth, and browser first-frame time still need the [deployment acceptance procedure](../deployment-acceptance.md). The later optional Compose profile is recorded separately in [the observability checkpoint](2026-10-18-observability-stack.md).
