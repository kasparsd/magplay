# 32-bit ARM image (linux/arm/v7)

Date: 2026-11-04. Host: Apple M1 Pro, Docker Desktop with QEMU user-mode emulation for `linux/arm/v7`. Not a 32-bit ARM device.

## Result

`magplay-core` builds and runs as `linux/arm/v7` with no code or dependency changes. The only Dockerfile change is that the install and build stages run on Alpine's `nodejs` and `npm` instead of `node:24-alpine`, which publishes no `linux/arm/v7` image. Alpine 3.24's `nodejs` is 24.22.1 on armv7, the same package the runtime stage already used.

| Check | Result |
| --- | --- |
| `docker build --platform linux/arm/v7 --target core` | succeeds in about 8 minutes under emulation; `npm ci` compiled nothing and the dependency tree matches the 64-bit images (no bufferutil, utf-8-validate or utp-native on any platform) |
| Image size | 88 MB unpacked (the 64-bit image is 107 MB), a 31 MB saved archive |
| `tools/scripts/check-docker.mjs` | passes: health, non-root, cached torrent, raw range, direct MP4, browser AC3 repackage, metrics, logging and graceful flush (needed a longer health wait than the 12 s the script allowed, because of emulation) |
| `docker run`, `process.arch` | `arm`, Node v24.22.1 |
| RouterOS 7.25.1 (ARM64 CHR, QEMU) | tarball imported (`arch: arm`), started, `healthcheck-status: good`, 52 MiB at start |
| arm64 and amd64 after the base change | arm64 `full` and amd64 `core` (emulated) build and pass `check-docker` |

## Not covered

- No 32-bit device, so no memory or speed figures. Under emulation `check-docker` reports CPU and resident memory that mean nothing for a real board.
- `linux/arm/v6` and below are not possible: Node 24 and Alpine's `nodejs` need ARMv7.
- The full image is not built for arm/v7. It would compile ffmpeg under emulation in CI, and a host that small does not transcode.
